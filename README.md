Комплексный проект системного и процессного анализа по автоматизации перевода сделки найма моряка в смарт-процесс комплектования судового экипажа с контролем сроков контрактов.

---

## 📌 Проблематика (AS-IS) и бизнес-цель (TO-BE)

* **Как было (AS-IS):** Данные о моряках, открытых судовых вакансиях и оплаченных счетах существовали изолированно. После оплаты сделки операционный отдел вручную заполнял судовые роли и переносил даты контрактов, из-за чего возникали просрочки смен экипажей на борту.
* **Как стало (TO-BE):** Реализована сквозная связь CRM-контура со смарт-процессом «Экипаж». При переходе сделки в статус `Оплачено` сущность экипажа генерируется автоматически, кандидат отображается во вкладке соответствующего судна, а планировщик задач за 30 дней до окончания контракта формирует задачу на подбор смены.

## 🔄 Архитектура сквозного процесса (BPMN Workflow)

Ниже представлена логика автоматической обработки и смены состояний:

```text
[ Сделка создана ]
       │
       ▼
[ Заполнение реквизитов: Кандидат, Вакансия, Судно ]
       │
       ▼
   / Статус \  ── (В работе / Счет выставлен) ──> [ Ожидание оплаты ]
   \ сделки?/                                             │
       │                                                  │
       │ (Оплачено) <─────────────────────────────────────┘
       ▼
┌────────────────── КОНТУР СМАРТ-ПРОЦЕССА ──────────────────┐
│                                                           │
│  1. Генерация записи в реестре «Экипаж»                  │
│  2. Привязка кандидата к объекту Судно (вкладка «Флот»)   │
│  3. Расчет дедлайна: DueDate = EndDate - 30 дней          │
│  4. Создание регламентной задачи координатору             │
│                                                           │
└─────────────────────────────┬─────────────────────────────┘
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
[ Моряк активен во флоте ]       [ Напоминание: найти смену ]
```

## 🗄 Модель данных и сущности (ER-логика)

В системе реализованы реляционные связи со строгими внешними ключами (`FOREIGN KEY`) и триггерами ссылочной целостности:

| Сущность | Назначение таблицы | Ключевые поля |
| :--- | :--- | :--- |
| **`contacts_seafarers`** | Справочник кандидатов и контактных данных | `contact_id` (PK), `full_name`, `rank_applied` |
| **`vessels_fleet`** | Реестр судов и флота компании | `vessel_id` (PK), `imo_number`, `vessel_name` |
| **`job_vacancies`** | Справочник вакантных судовых должностей | `vacancy_id` (PK), `vessel_id` (FK), `rank_title` |
| **`crm_deals`** | Коммерческая сделка по найму | `deal_id` (PK), `contact_id` (FK), `deal_stage` |
| **`smart_process_crews`** | Активный смарт-процесс закрепления экипажа | `assignment_id` (PK), `vessel_id` (FK), `contract_dates` |
| **`scheduled_tasks`** | Автоматические напоминания и задачи | `task_id` (PK), `assignment_id` (FK), `due_date` |

> Полный скрипт создания схемы данных доступен в файле [`/database/schema.sql`](./database/schema.sql).

## 🔌 Контракт интеграции (REST API)

Спроектирован метод создания элемента смарт-процесса по событию успешной оплаты сделки:

* **Endpoint:** `POST /api/v1/smart-processes/crew/generate-from-deal`
* **Формат данных:** `application/json`
* **Спецификация:** Полный контракт по стандарту OpenAPI 3.0 доступен в файле [`/api/openapi-spec.yaml`](./api/openapi-spec.yaml).

### Пример тела запроса (Request Payload)
```json
{
  "dealId": 5401,
  "contactId": 1204,
  "vesselId": 88,
  "positionTitle": "Старший помощник капитана",
  "startDate": "2026-12-01",
  "endDate": "2027-04-01"
}
```

### Пример успешного ответа (201 Created)
```json
{
  "crewAssignmentId": 9812,
  "scheduledTaskId": 304,
  "status": "ACTIVE",
  "reminderDate": "2027-03-02"
}
```

## 📈 Бизнес-эффект от внедрения

1. **Исключение человеческого фактора:** 100% синхронизация данных между коммерческим отделом и операционной службой флота.
2. **Предотвращение простоев флота:** Автоматическое планирование смены за 30 календарных дней исключает задержки судов в портах из-за некомплекта экипажа.
3. **Единый источник правды:** Вся история контрактов и текущий состав экипажа отображаются в реальном времени прямо в карточке судна.
